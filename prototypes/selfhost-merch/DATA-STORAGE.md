# Где хранятся данные — актуальная схема от 29 октября 2026

Только синтетический серверный стенд. Корпоративная БД ещё не предоставлена, реальный Supabase не копируется. После переноса все компоненты приложения и данные должны находиться в согласованном корпоративном контуре; здесь это Docker volumes среды разработки.

| Данные | Хранилище |
|---|---|
| Профили, доступы, заказы, варианты, остатки, картинки | PostgreSQL `merch_selfhost_demo`, volume `database` |
| Учётные записи тестового Keycloak | Отдельный volume `identity-provider`, не БД мерчшопа |
| Серверные сессии | PostgreSQL; оригинальный токен только в HttpOnly cookie |
| Письма | Зашифрованный `demo_outbox`; настоящего SMTP нет |
| Защита от восстановления удалённых людей | Отдельный `deletion-ledger`, `/data/ledger/deletions.json` |
| Архивы БД и прежних файлов | AES-GCM `.local/backups`; имя установки проверяется при restore |
| Секреты | `.local/demo.env`, вне Git; production требует secret manager |
| Старые сгенерированные картинки | `product-files`, сохранён для совместимости; новые загрузки идут в БД |

## Профили и авторизация

Корпоративные: ФИО, подтверждённая рабочая почта, стабильные `iss + sub`, кадровые БЮ и юрлицо, будущая дата удаления из источника (если известна), магазин/раздача/раздел и активность. Не требуется импорт полного кадрового справочника. Допуск — отдельные правила по человеку/группе/юрлицу; поиск людей пока синтетический адаптер.

Массовый персонал: ФИО, юрлицо, должность, телефон, HMAC ПИНФЛ. Исходный ПИНФЛ присутствует в передаваемом HR-файле и оперативной памяти обработки, в БД/ссылку/письмо/аудит не записывается. Он не является секретным паролем: для активации нужна ещё персональная случайная ссылка. Сессия — 30 дней без аппаратного ID; после выдачи/отправки закрывается раньше. Источника увольнений массового персонала нет; пропуск строки при следующем импорте не удаляет человека.

Новички: ФИО, личная почта, время подтверждения, срок приглашения и получения. Только Welcome pack, одноразовые ссылки на 20 минут, повторный вход к тому же аккаунту. Корпоративного/личного пароля приложение не создаёт.

В корпоративной сессии на 15 минут — код юрлица/группы и активность для перепроверки допуска. ФИО/email/БЮ/юрлицо не копируются в снимок заказа. Случайные UUID, HMAC и связанная техническая информация остаются персональными/псевдонимизированными данными, не гарантированным обезличиванием.

## Товары и заказы

В БД хранятся тип/название/раздел, размеры, цвета, количество/резерв и изображения (`bytea`, MIME). PNG/JPEG/WebP до 2 МБ. Выдача картинки через сервер с проверкой магазина/раздела, без прямого доступа браузера к БД. Не принимается произвольный SVG пользователя; старые SVG-заглушки доверенно сгенерированы сервером.

Заказ связан с аккаунтом, хранит позиции, статус и время; офис/отправка отмечаются отдельно. QR — случайная строка без ПД, хэш плюс временно зашифрованный оригинал. Доставка фиксируется администратором без интеграции перевозчика; полного адресного сценария рабочего сайта здесь пока нет.

## Удаление

- При получении портального события увольнения/удаления — синхронное удаление операционных записей и закрытие сессий до успешного ответа. Реальный источник пока не подключён.
- По известной будущей дате — worker каждые 5 секунд, независимо от входа; сервер запрещает доступ уже при наступлении срока.
- Для всех получивших/отправленных заказов — два календарных месяца по Asia/Tashkent от `fulfilled_at`, не 60 дней. Доступ закрывается при выдаче/отправке, а не через два месяца.
- Не завершившим — предложенный отдельный предел два месяца после закрытия раздачи; этот случай требует утверждения.
- Прикладные события — 30 дней либо раньше вместе с соответствующим участником. Истёкшие токены и счётчики чистятся worker.

Удаляются профиль, аккаунт, разрешение по конкретному человеку, сессии, приглашения, письма, персональные заказы/позиции/связанные движения и аудит участника. Незавершённый резерв освобождается. Чужие движения сохраняются с обнулением ссылки на удалённого исполнителя. Товары/картинки/остатки и суммарное количество полученного/отправленного сохраняются без ID получателя; малые группы требуют оценки косвенной идентификации.

## Что требует отдельного регламента

Журнал удаления содержит UUID и HMAC метки источника; они нужны для запрета восстановления/повторного входа удалённой корпоративной личности. Это технические, потенциально связанные с человеком данные, автоматический TTL меток в mock **не настроен**. Их период хранения/минимизацию надо согласовать отдельно.

Удаление из рабочей БД не стирает старый backup. Демо-ротация архивов старше 7 дней работает только при запуске backup-команды, расписания нет. Restore повторно применяет независимый журнал до открытия API, очищает сессии/ссылки и оставляет раздачи закрытыми для сверки операций после точки копии. Это не production PITR.

Очистка не управляет файлами у HR/на компьютере, Keycloak, инфраструктурными/SMTP-журналами, скачанными картинками, CSV и распечатками. После удаления профиля нет гарантии распознать того же человека с другим email; долгосрочный факт выдачи/запрет повторного участия требует отдельного учётного источника. Настоящие сроки, право обработки личной почты и ПИНФЛ, backup/log lifecycle и технические метки согласуются с ИБ/DPO.
