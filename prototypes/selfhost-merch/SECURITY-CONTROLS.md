# Меры защиты и условия корпоративного запуска

30 октября 2026. Только синтетический прототип, не подтверждение соответствия ИБ. Рабочий Vercel не изменён.

## Реализовано

- Серверная проверка роли, магазина и раздела. Корпоративный вход не даёт роль администратора. Параметризованный SQL, отдельные роли БД приложения, миграций и очистки.
- OIDC Code + PKCE, JWT/JWKS/issuer/audience/nonce/state, серверные HttpOnly/SameSite сессии, CSRF/Origin проверки пользовательских изменений. Пароль и токены IdP не сохраняются.
- CSP, no-store, no-referrer, nosniff; предел тела запроса и HTTP ожиданий. Для email-ссылок есть ограничения частоты; универсального rate limit нет.
- Прикладные события PostgreSQL: у merch_app нет UPDATE/DELETE на demo_events. Владелец БД всё равно может изменить записи: это не неизменяемый архив.
- Структурированный аудит в stdout для API, администрирования, авторизации и кадрового API: время, категория, HTTP результат, случайный request_id и UUID аутентифицированного исполнителя. Отказы/прерывания тоже фиксируются. URL, query, тело, заголовки, cookie, токены и исключения не выводятся. UUID также потенциально персональные данные.
- X-Request-ID создаётся сервером, клиентский идентификатор не принимается. У анонимного входа actor_id пустой. completed означает завершённый HTTP-ответ, не бизнес-успех. Этот аудит не содержит объекта изменения или before/after; предметные события/складские движения существуют отдельно. Полнота корпоративного аудита требует проверки.
- Docker json-file ограничен тремя файлами по 10 МБ на контейнер. Это предел объёма, не срок хранения. Без сборщика старые события теряются при ротации. Удаление профиля не удаляет его UUID из внешних логов автоматически.
- Закрытие доступа при выдаче/отправке, очистка ПД через два календарных месяца, подписанные mock кадровые события, зашифрованные backup и независимый журнал удаления. Ограничения описаны в DATA-STORAGE.md и LIFECYCLE.md.

## До реального запуска

| Мера | Ответственные |
|---|---|
| Корпоративные СЗИ, защита ОС, обновления и сканирование уязвимостей | Инфраструктура и ИБ |
| HTTPS, Secure cookie, TLS БД с проверкой сертификата, сетевые ACL и отсутствие публичной БД | Разработчики и инфраструктура |
| Secret manager, ротация ключей/паролей, минимальные права | Инфраструктура и разработчики |
| Коллектор/SIEM для app/DB/IdP/ingress, защита журналов от изменения, контроль доставки и оповещения | ИБ и инфраструктура |
| Каталог обязательных событий, идентификация объектов, доступ и календарные сроки хранения журналов | ИБ/DPO и разработчики |
| Rate limit, защита от перебора/перегрузки и доверенная proxy-конфигурация | Инфраструктура и разработчики |
| Настоящий Keycloak, MFA администраторов, кадровые события с retry/сверкой | Команда портала и ИБ |
| Backup/PITR, проверка восстановления, RPO/RTO, уничтожение копий и технических меток | Инфраструктура, владелец и DPO |
| Перенос в полный интерфейс, security review и нагрузочные проверки | Разработчики и ИБ |

Локальный HTTP без Secure cookie, внутренний трафик без TLS и секреты Docker env разрешены только для изолированных вымышленных данных. DEMO_ONLY намеренно запрещает реальные адреса. Этот Compose не является production-конфигурацией; не отключать ограничение для реального запуска.
