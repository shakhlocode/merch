# Результаты проверки — 23 октября 2026

## Выполнено

- 6 автоматических модульных проверок: ограничения demo-конфигурации, PKCE S256, доверенные claims, подпись/issuer/audience/срок JWT, запрет подмены кадровых полей и прав, ограничения товаров/получения.
- 9 групп браузерных/интеграционных сценариев с настоящим отдельным Keycloak 26.4.2 и отдельной PostgreSQL 17:
  1. Анонимный доступ к данным и поддельный callback отклоняются.
  2. OIDC/PKCE-вход, неизменяемые кадровые поля, HttpOnly/SameSite cookie, сохранение локального аккаунта и старого заказа.
  3. Повтор callback, CSRF, чужой Origin, подмена ФИО/магазина и недоступный ПВЗ отклоняются; форма и API создают заказ с серверным снимком личности.
  4. Welcome pack ограничен своим магазином, товарами и офисным получением; чужая история не видна.
  5. Пользователь Keycloak без разрешения реестра и отключённый в Keycloak пользователь не получают доступ.
  6. Смена email и вход из существующей SSO-сессии сохраняют локальный ID и заказы.
  7. Настоящее подписанное back-channel logout уведомление отзывает локальные корпоративные сессии; неподписанное отклоняется.
  8. Две конкурентные активации приглашения дают одного победителя; гость не вводит почту/пароль и сохраняет вход после перезагрузки.
  9. Локальный logout удаляет серверную сессию; возврат старой cookie не восстанавливает доступ.
- Повторная установка с чистыми volumes именно `merch-identity-demo`, запуск сгенерированного realm и сохранение конфигурации при повторном `npm run init`.
- `npm audit --omit=dev`: известных уязвимостей серверных зависимостей этого прототипа не найдено на момент проверки. Это не анализ всех зависимостей рабочего мерчшопа и не сканирование образов.
- Production-сборка основного мерчшопа: стандартная `npm run build` и проверка через webpack прошли. Lint основного репозитория: 0 ошибок, существующее предупреждение `ProductImage.tsx` о `<img>`.

В sandbox первоначальная стандартная Turbopack-сборка упиралась в ограничения дочерних процессов/операций ОС. Повторный стандартный запуск с разрешёнными операциями завершился успешно. Веб-приложение и БД production при проверках не изменялись.
