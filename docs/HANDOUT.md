# Офисная выдача по QR-коду

В «Товарах» администратор создаёт товар, варианты и начальные остатки.
Поступления добавляют единицы, корректировка со знаком минус убирает их.
Для корректировки нужна причина. Зарезервированные единицы списать вручную
нельзя: сначала измените или отмените соответствующий заказ. Товар можно
отключить в редакторе карточки, сохранив историю.

Новые заказы видны администраторам соответствующего магазина. После сборки выберите статус
**Можно забирать** и сохраните. Откройте **Выдача** (`/admin/issue`):

- USB/Bluetooth 2D-сканер с поддержкой QR в режиме клавиатуры (HID) вводит код в поле на странице.
  По умолчанию после 20 цифр автоматически открывается карточка заказа, Enter не нужен.
  Сканеры с Enter или Tab также поддерживаются. В карточке проверьте получателя и расположение, затем нажмите «Выдать заказ».
  До этого статус и остатки не меняются.
- Для ручного ввода можно снять «Автоматически искать после ввода 20 цифр»
  и открыть карточку кнопкой «Найти заказ» или Enter. Неполный код не отправляется; начальные
  нули сохраняются. Неподготовленный заказ не выдаётся даже с правильным кодом.
- Кнопка камеры включает чтение QR на телефоне или ноутбуке. Браузеру нужен доступ
  к камере. При проблемах можно вручную ввести 20 цифр.
- Скан показывает номер, получателя, место хранения и состав. Только отдельное
  подтверждение выдаёт готовый заказ целиком. Повторный скан показывает «Уже выдан».

Состав можно менять в карточке заказа: убрать позицию, добавить другую,
заменить размер удалением старого и добавлением нового варианта. Лимит —
три разных товара по одной единице. Сохранение атомарно пересчитывает резерв
и снимает готовность. Проверьте сборку и снова отметьте «Можно забирать».
Отправленные, выданные и отменённые заказы менять нельзя. При конфликте
версий обновите страницу; чужие изменения не перезаписываются.

Офисный сотрудник видит QR-код в «Моих заказах». Код содержит случайные
20 цифр без персональных данных, номер заказа показан отдельно. Начальные
нули важны. Картинка генерируется в приложении, без внешнего сервиса.
После оформления и в «Моих заказах» кнопка **Скачать QR-код** сохраняет PNG
с QR-кодом и читаемым номером заказа. Файл можно открыть на телефоне
без входа на сайт и показать при выдаче. Он содержит тот же код, без ФИО,
телефона и других личных данных; скачивание не меняет статус и остатки.
Файл создаётся в браузере, без отправки кода стороннему сервису.

Удалённый сотрудник не получает QR-код. В заказе показан ответственный,
который согласует получение и при необходимости сообщит трек-номер. По
умолчанию назначается первый активный администратор; его можно сменить в
карточке заказа. Удалённую отправку и завершение отмечают вручную.
Интеграция с WMS/перевозчиками не добавлялась.

## Учёт

- При заказе резерв увеличивается, свободное количество уменьшается.
- При выдаче уменьшаются общий остаток и резерв. Свободное количество не
  уменьшается повторно: эта единица уже была зарезервирована.
- Статус `received` («Получен»), статус выдачи, дата, выдавший администратор,
  складское движение и событие `order_events` фиксируются одной транзакцией.
- Блокировка заказа и уникальное событие выдачи защищают от параллельных
  сканирований. Ошибка записи откатывает всю операцию.
- Проверки роли есть в API и SQL. Выдать может любой активный администратор.
  Код служит идентификатором; общедоступного endpoint выдачи нет.
- Новый, отменённый и удалённый заказ не выдаётся по коду. Офисный заказ нельзя
  вручную переключить в «Получен», включая обращение к прежнему RPC.

## Миграции и проверка

На существующий проект по порядку применяются две новые миграции:
`20261014000100_ready_status.sql`, затем `20261014000200_office_handout.sql`.
Первую необходимо закоммитить перед выполнением второй. На новый пустой проект
применяются все миграции по порядку. Базовую миграцию повторно не запускайте.

`npm run db:test` проверяет прежние сценарии, новые переходы, пересчёт резерва,
откат при недостатке остатков и ошибке аудита, удалённые заказы, права доступа,
конкурентное оформление и два одновременных сканирования.

QR из страницы заказа, скачанного PNG и наклейки A4 проверяется декодером. Автоматический тест подаёт изображение в видеопоток камеры браузера и проверяет однократную выдачу. Это не заменяет проверку реальной камеры и принтера. Отдельный сканер должен поддерживать QR (2D), HID и чтение с экрана; старый одномерный лазерный сканер не подойдёт.


## Подтверждение выдачи после сканирования (29 октября 2026)

В карточке заказа при сборке заполните свободное поле «Где лежит заказ», например «1 коробка» или «2 стеллаж», и сохраните изменения. Новый справочник адресов и обязательный формат не вводятся. Старые заказы без указанного места остаются доступны; выдающий увидит предупреждение об отсутствии расположения.

Сканирование камерой, 2D-сканером либо ручной ввод теперь выполняют **только поиск** через `/api/admin/issue/lookup` → `admin_lookup_pickup`. Показываются получатель, расположение, состав и возможность выдачи. На телефоне камера и карточка результата открываются поверх страницы на высоту экрана, без прокрутки к видео.

Только отдельная кнопка «Выдать заказ» вызывает `/api/admin/issue` → `admin_confirm_pickup`, с ID и версией прочитанного заказа. Изменение заказа между поиском и выдачей требует нового сканирования. Подтверждение вызывает прежнюю атомарную `admin_issue_order`; готовность, запрет удалённых заказов, складские движения, исполнитель, журнал и защита повторной выдачи сохраняются. Повторное подтверждение уже выданного заказа возвращает исходную квитанцию. Старый API-запрос без явного подтверждения отклоняется.

Миграция `20261029002200_confirm_handout.sql` добавляет две функции, не меняет существующие записи/остатки и использует имеющееся `orders.storage_location`. Применить перед публикацией нового клиента.

Проверено локально: production-сборка, TypeScript, lint (один прежний img-warning), полный набор SQL-тестов и одновременные подтверждения двумя администраторами. Мобильный React-компонент проверен на вымышленных API-ответах: поиск не выдаёт, закрытие карточки не выдаёт, кнопка подтверждает, старый/неготовый заказ блокируется, камера занимает viewport. Физическая камера телефона и опубликованная версия с этой миграцией пока не проверялись.
