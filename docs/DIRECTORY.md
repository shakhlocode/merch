# Реестр сотрудников и импорт

Право заказать мерч теперь определяется наличием активной записи в employee_directory. Проверка стажа 3 месяца отменена по требованию владельца. Дата найма сохранена для исторических данных, но стала nullable и не запрашивается в форме. Поля формы: email, ФИО, необязательный external_id (внутренний идентификатор, не UUID аккаунта). Непустой идентификатор уникален. Существующие сведения о должности/подразделении сохраняются в БД. Изменения идентификатора попадают в аудит. Аккаунт связывается с реестром по email; добавление в реестр не создаёт аккаунт и не отправляет письма. Доступ можно отключить и вернуть отдельными кнопками редактора.

Кнопка «Загрузить Excel / CSV» принимает первый лист .xlsx или CSV UTF-8, до 5 МБ, максимум 2000 строк. Заголовки Email, ФИО, Идентификатор; последний столбец необязателен. Шаблон: public/templates/employees.csv. Идентификаторы с ведущими нулями следует хранить как текст в Excel. Предпросмотр и проверка файла выполняются в браузере; сохранение запускается отдельной кнопкой. Внутри файла повторяющиеся email/идентификаторы и неверные строки блокируют импорт. Сервер повторно проверяет обязательные данные и права активного администратора.

Импорт добавляет новые записи одной транзакцией. Существующие email (без учёта регистра) пропускаются, их ФИО, идентификатор и статус не меняются. Конфликт идентификатора или ошибка записи откатывает всю загрузку. Повторный импорт того же списка не создаёт дубликатов. Не включённые в файл сотрудники не удаляются и не отключаются.

## Архив товаров

Архив использует существующее products.is_active=false. Новая отдельная копия товара не создаётся. По умолчанию админы видят действующие товары; «Показывать → Архив» позволяет восстановить товар. Старые отключённые товары тоже находятся в архиве. Клиентские каталог и Welcome-pack показывают только активные товары. Архивирование не меняет остатки, не отменяет оформленные заказы и не удаляет историю. Резерв существующего заказа сохраняется, новый заказ архивного товара недоступен. Восстановление возвращает прежние данные и остатки. Выключенные варианты отдельно не включаются при восстановлении товара.

Варианты товара и операции с остатками представлены вертикальными карточками с подписями, без таблицы с горизонтальной прокруткой. При большом числе вариантов остаётся обычная вертикальная прокрутка редактора.

Миграция: 20261014000400_directory_import.sql. npm run db:test включает проверки импорта, приватности реестра, архива, истории, резервов и прежних сценариев выдачи.

## Сроки доступа

С миграции 20261014000500_access_periods.sql у записи реестра есть access_mode: unlimited (бессрочно), until_date (по дату включительно, по времени Ташкента) или one_order (до получения одного заказа). Старые записи получают unlimited, их действующий статус не меняется. Условия is_active и тип доступа проверяются вместе. При импорте выбранный в форме тип назначается всем новым строкам, существующие записи по-прежнему пропускаются.

Разовый доступ допускает один незавершённый заказ. Отмена/отклонение освобождают эту возможность. После перехода заказа в received (скан готового офисного заказа или ручная отметка получения удалённого) access_used_at заполняется в той же транзакции, что статус, складские движения и аудит. Ошибка откатывает всё. Повторный скан не списывает товар и не расходует повторно выданный доступ. Администратор может явно выдать доступ ещё на один заказ в редакторе сотрудника. Изменение типа/срока доступа также сбрасывает использованный разовый доступ; простое редактирование имени/идентификатора — нет.

Истечение срока вычисляется при каждом запросе без cron. SELECT-политики Supabase закрывают пользователю каталог и заказы даже с ранее выданной авторизационной сессией. Страницы магазина проверяют has_system_access на сервере; уже открытый магазин проверяет доступ каждые 15 секунд и при возвращении в окно. Устаревшее изображение на экране до проверки не позволяет оформить новый заказ. Supabase Auth-аккаунт не удаляется; после продления можно снова открыть магазин. Права действующего администратора сохраняются для управления магазином, независимо от ограничений его записи получателя мерча.

Блок дедлайна раздачи удалён из дашборда. Исторические настройки и данные заказов не удаляются.
