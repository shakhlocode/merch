Конфигурация ESLint переведена на flat exports текущего Next. Новые React Compiler диагностики оставлены предупреждениями: React Compiler в приложении не включён. React 18 сохранён; его deprecated support в Next 16 — отдельная будущая миграция, не часть отчётной RCE.

## 3.2 — Отзыв администратора

Новая миграция [`20261103002300_security_review.sql`](../supabase/migrations/20261103002300_security_review.sql) **явно переопределяет** admin_create_product и admin_import_employees. Обе проверяют public.is_admin(), сохраняя выбранный магазин и RLS. Нет зависимости от employees.is_admin и текстовой подмены определения функции. Владелец — merch_executor без BYPASSRLS, execute только authenticated, PUBLIC/anon отозваны.

Тест прямых RPC: legacy flag=true, активный профиль и реестр, но роль shop_admins отозвана — отказ. Новый unit-admin с legacy flag=false — успех. Подмена магазина, чужой товар и anon — отказ. Старые миграции сохранены как история: эффективные определения устанавливает новая миграция.

## 3.3 — Вариант + начальный остаток

В той же миграции создана **admin_create_variant**: проверка роли/магазина и входных значений, вставка варианта и движения в общей SQL-транзакции. API [`products/route.ts`](../app/api/admin/products/route.ts) вызывает одну RPC вместо двух независимых INSERT. Ответ содержит прежний variant.id, типы Supabase обновлены. Проверены нулевой остаток и принудительная ошибка второго INSERT: вариант тоже откатывается.

Операция не получила автоматические повторные попытки. После неопределённого сетевого результата нужно сверить каталог; уникальный SKU не даёт незаметно создать второй одинаковый вариант. Полный протокол идемпотентности — отдельная доработка, не заявляется реализованным.

## 3.4 — Файлы, заголовки и ошибки

- [`lib/security/image.mjs`](../lib/security/image.mjs), загрузчик API: клиентские MIME/расширение не считаются доказательством. PNG/JPEG/WebP/GIF проверяются по сигнатуре, декодируются Sharp, ограничены 5 МиБ и 16 млн пикселей, повторно кодируются в статичный WebP без исходных метаданных. MIME/расширение задаёт сервер. GIF становится первым кадром, подсказка интерфейса обновлена. Старые файлы в Storage автоматически не переписываются: для них требуется отдельная инвентаризация/перезагрузка.
- [`proxy.ts`](../proxy.ts), [`headers.mjs`](../lib/security/headers.mjs), next.config.mjs: CSP с новым nonce на запрос, frame-ancestors none, X-Frame-Options DENY, nosniff, no-referrer, Permissions-Policy. Камера разрешена только своему origin. Для существующего inline CSS оставлено style-src unsafe-inline; скрипты защищены nonce, unsafe-eval только development. HTTPS-изображения разрешены для существующих вручную указанных фото; script/connect не разрешены всем внешним сайтам.
- HTML принудительно динамический и без общего кэша для безопасности nonce. Callback-скрипт получает nonce. Inline onclick печати заменён обработчиком, чтобы CSP не ломала кнопку. Нельзя кэшировать эти HTML-ответы в CDN с общим nonce.
- HSTS в production max-age 1 год, без includeSubDomains/preload. До публичного развёртывания обязательно обеспечить HTTPS и сертификаты. HSTS не настраивает TLS сам.
- [`public-error.mjs`](../lib/security/public-error.mjs): точный allowlist безопасных сообщений и кодов; неизвестные SQL/Storage/Auth/exception сообщения наружу не возвращаются. Закрыты также helper requireAdmin, вложенные результаты приглашений и диагностический redirect авторизации. Это не запрет административного доступа к данным, которые предусмотрены самим интерфейсом.

## Применение

1. Проверить этот commit в ИБ, подготовить резервную копию и тестовое окружение.
2. На уже развёрнутой схеме применить **только новую** миграцию через штатный канал, затем обновить приложение. Не переигрывать начальную миграцию поверх рабочей БД.
3. Для чистой тестовой БД применить все миграции по порядку. Прямой `npm run db:test` использует отдельный временный контейнер.
4. Проверить реальные заголовки HTTPS/ingress, обновление схемы PostgREST и smoke-сценарии. Учесть, что ранее созданные изображения не очищены автоматически.
