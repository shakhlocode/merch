# Вход без почты и восстановление

Персональное приглашение с идентификатором активируется один раз, закрепляя аккаунт за записью реестра. Браузер сохраняет сессию. Это не аппаратная привязка к телефону: нужно пользоваться тем же браузером, лучше Chrome, а не встроенным окном мессенджера.

В «Сотрудниках» возле активированной записи есть «Восстановить вход». Для гостевого аккаунта без пароля администратор сначала проверяет личность лично или по корпоративному каналу, затем подтверждает создание новой ссылки. Ссылка действует до 24 часов (не дольше доступа сотрудника), требует прежнего идентификатора и используется один раз. Старые приглашения отзываются. Новый вход сохраняет тот же auth user ID, текущий заказ, историю, магазин, срок и лимиты. Восстановление не обнуляет полученный заказ, не продлевает истёкший доступ и не меняет роль. Для обычного аккаунта с почтой используется штатное восстановление пароля.

Миграция 20261016001900 вводит дополнительную проверку лишь для явно восстановленных аккаунтов. Сеансы, созданные до сброса, сразу теряют доступ к приватным таблицам и бизнес-RPC, даже если JWT ещё не истёк. Само наличие старого Auth JWT может сохраняться до истечения, но он не открывает магазин и приватные данные. Таблица отсечек не доступна клиентам. Записываются события browser_access_reset и browser_access_restored.

Приглашение не доказывает личность: до первой активации его можно добровольно передать вместе с идентификатором. QR заказа также можно переслать; сверка получателя при выдаче остается необходимой. Нельзя обещать абсолютный запрет передачи доступа.

Почтовые приглашения используют существующий SMTP-поток и его настройку INVITE_EMAIL_ENABLED. Восстановление гостевого входа не требует SMS или почты.
